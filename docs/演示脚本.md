---

## 1. 演示目标与角色分工

| 成员 | 演示角色 | 负责环节 |
|---|---|---|
| A | admin / data_engineer | 数据接入、数据集版本、权限与审计 |
| B | reviewer | 算法指标核验、报告签发 |
| C | annotator / screener | 标注闭环、筛查—报告主链路 |

> 职责分离要点：标注（C）→ 审核（B）→ 筛查复核（C）→ 签发（B），全程体现「起草—审核—签发」分离。

---

## 2. 环境准备

1. 前端：`cd frontend && npm install && npm run dev`，浏览器打开 `http://localhost:5173`。
2. 当前为 Mock 模式（后端未就绪）；后端就绪后设 `VITE_USE_MOCK=false` 并启动 `backend/` 与算法 Worker。
3. 演示账号（Mock 密码任意）：`admin` / `data_engineer` / `annotator` / `screener` / `reviewer`。

## 3. 演示流程

### 场景 0：开场与合规声明（30 秒）
- 打开登录页，指出标题与底部免责声明「仅供科研/教学使用，不作为临床诊断依据」。
- 台词：「平台定位是乳腺超声影像的数据接入—标注—训练评估—辅助筛查—报告审计一体化原型，仅用于科研教学。」

### 场景 1：数据接入（A，1 分钟）
- 以 `data_engineer` 登录 → 「数据接入」。
- 上传 BUSI ZIP → 展示校验/导入阶段进度 → 计数 780 张、重复 0。
- 「数据集版本」页展示冻结版本 546/118/116。

### 场景 2：标注闭环（C 标注 + B 审核，2 分钟）
- 以 `annotator` 登录 → 「标注任务」→ 领取 → 「掩膜编辑器」。
- 演示：画笔涂抹 → 橡皮擦除 → 多边形勾边 → 撤销/重做 → 保存草稿 → 提交审核。
- 切换 `reviewer` 登录 → 审核通过。
- 台词：「掩膜以 COCO RLE 存储，支持多病灶、版本与审核留痕。」

### 场景 3：筛查—报告主链路（C 筛查 + B 签发，3 分钟）
- 以 `screener` 登录 → 「筛查工作台」→ 领取检查 → 检查详情。
- 演示影像查看器缩放/平移 → 点击「模型分析」→ 展示推理结果面板（面积占比、平均概率、质量标记）。
- 调整掩膜透明度 → 医生复核（接受/修改/驳回）→ 查看操作时间线。
- 点击「撰写报告」→ 编辑所见/印象/建议 → 提交审核。
- 切换 `reviewer` 登录 → 签发报告 → 报告状态变为「已签发」，展示免责声明。

### 场景 4：统计与审计（C，1 分钟）
- 「统计看板」：总览计数、模型指标图（3 种子均值 ± 标准差）、标注进度、筛查统计。
- `admin` 登录 → 「审计日志」：展示登录、导入、审核、推理、签发全量留痕。

### 场景 5：模型与指标（B 备份，30 秒）
- 「模型与指标」：展示 3 个种子版本 Dice/精确率/召回率/HD95，启用/回滚操作。

## 5. 风险与备用方案

| 风险 | 应对 |
|---|---|
| 后端未就绪导致真实链路不可用 | 使用 Mock 模式完整演示前端主链路，并说明接口已按契约对齐 |
| CPU 推理慢导致演示超时 | 使用预置推理结果，演示中「模型分析」即时返回 |
| 网络异常无法访问 GitHub | 本地 `npm run dev` 已可完整运行，不依赖外网 |
| 录屏遗漏关键步骤 | 按本脚本场景顺序录制，每场景一镜到底 |
